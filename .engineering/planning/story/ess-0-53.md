## Outcome

The repository runs on ESS 0.53.0, the newest release. The `ess` CLI that CI installs and the
`ess-conformance` and `ess-primitives` dependencies all name `0.53.0`, the suite and schemas are
regenerated with that release, and `task check` passes.

## Why

Operator rule, 2026-10-05: "ALWAYS upgrade to most recent ESS" (`~/beyond10x/AGENTS.md`, "ESS
version"). `story:ess-latest` moved the repository to 0.52.0. The newest release is 0.53.0
(`https://api.github.com/repos/beyond10x/ess/releases/latest`, read 2026-10-06).

## Acceptance

- `.github/workflows/gate.yml`, `checks/conformance/Cargo.toml` and `Cargo.lock` no longer pin ESS
  `0.52.0`; all three name `0.53.0`. The workflow's pinned SHA-256 is the one in the 0.53.0
  release's `SHA256SUMS`.
- `contracts/suite.json` and `contracts/schema/schema/` are regenerated with 0.53.0 in the same
  commit.
- `ess specify validate --path spec`, the conformance check and `RUSTUP_TOOLCHAIN=1.98.0 task check`
  all exit 0. The scenario totals equal those at the story's base commit. Any difference is listed
  scenario by scenario, with its cause, in the commit message and in the story's `test_result`
  evidence record, and `contracts/baseline.json` moves only with that list.
- `AGENTS.md` names 0.53.0 wherever it named 0.52.0.

## ESS first

None needed: this moves the toolchain only. Every refusal and every regenerated difference is
reported.

## Scope (inferred)

`.github/workflows/gate.yml`, `checks/conformance/Cargo.toml`, `Cargo.lock`, `contracts/`,
`AGENTS.md`.

## Ordering

This story runs alone, in a wave of its own. It regenerates all of `contracts/` and rewrites
`Cargo.lock` and `checks/conformance/Cargo.toml`, so any story that adds scenarios or a
dependency collides with it. Run it before the next such story, which today is any story under
`epic:gateway`, `epic:hosting` or `epic:gateway-features`.
