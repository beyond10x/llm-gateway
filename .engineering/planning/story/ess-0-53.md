## Outcome

The repository runs on ESS 0.56.0, the newest release. The `ess` CLI that CI installs and the
`ess-conformance` and `ess-primitives` dependencies all name `0.56.0`, the suite and schemas are
regenerated with that release, and `task check` passes.

## Why

Operator rule, 2026-10-05: "ALWAYS upgrade to most recent ESS" (`~/beyond10x/AGENTS.md`, "ESS
version"). `story:ess-latest` moved the repository to 0.52.0. The newest release is 0.56.0
(`gh release list -R beyond10x/ess`, read 2026-10-08: 0.56.0 is `isLatest`, published
2026-10-07T23:16:28Z). The story id keeps its 0.53 name; it was drafted when 0.53.0 was newest.

## Acceptance

- `.github/workflows/gate.yml`, `checks/conformance/Cargo.toml` and `Cargo.lock` no longer pin ESS
  `0.52.0`; all three name `0.56.0`. The workflow's pinned SHA-256 is the one in the 0.56.0
  release's `SHA256SUMS`.
- `contracts/suite.json` and `contracts/schema/schema/` are regenerated with 0.56.0 in the same
  commit.
- `ess specify validate --path spec`, the conformance check and `RUSTUP_TOOLCHAIN=1.98.0 task check`
  all exit 0. The scenario totals equal those at the story's base commit. Any difference is listed
  scenario by scenario, with its cause, in the commit message and in the story's `test_result`
  evidence record, and `contracts/baseline.json` moves only with that list.
- `AGENTS.md` names 0.56.0 wherever it named 0.52.0.

## ESS first

None needed: this moves the toolchain only. Every refusal and every regenerated difference is
reported.

## Ordering

No other story that edits `spec/`, adds or changes a scenario, adds a dependency or changes the
gate runs beside this one. It regenerates `contracts/suite.json` and `contracts/schema/schema`, and
rewrites `Cargo.lock` and `checks/conformance/Cargo.toml`, so every such story collides with it.
In wave 2026-10-08-w03 it merges into the integration branch first, and
`story:gateway-deployment` forks from that merge. `story:container-image` touches none of those
files and runs beside it.
