The feed has four link states and a snapshot that can go stale while the page keeps showing the old
numbers, but the replay test refuses any state whose status is not `live`, so no scenario plays the
others: no layout, axe, key-data or contrast measurement and no shot exists for polling, offline or
a snapshot that stopped updating. A monitor that shows old numbers without saying so would be S2;
what the page shows in those states is unknown, which is why this is filed as a gap of the loop
(class `engine`, S3) and not as a page defect. Raise to S2 if the first replay shows no visible
cue. Sessions: none. Cost M. One line: add replay scenarios for a dropped stream (polling), an
unreachable gateway (offline) and a snapshot older than the poll interval, and gate that the header
status names the state in words.

R-06 tools: the scenario `offline` replays two states of traffic, then the stream errors and every snapshot fetch answers 503, and the page's poll runs once (`lose-connection` in `e2e/harness.ts`). It is measured like every scenario (layout, axe, key data, copy, shots), and the replay gate asserts "live" before the loss and a non-live state in words after it: the header reads "offline". Between the two the page says "polling every 5 s". So the page does show the loss, and the record stays S3. Still open: a snapshot that stops updating while the stream stays open is not replayed, and nothing on the page names the age of the data.
